# ตัวหลักของทีม (baseline)

ตัวหลักคือโค้ดที่ tag `baseline-0.72635` บน branch `main` ได้คะแนนบน Kaggle **0.72635** เมื่อ 12 พ.ย. 2026 บนข้อมูลชุดที่ผู้จัดแก้แล้ว

งานที่ใครทำต่อ ให้เทียบกับตัวเลขในตารางนี้ก่อนอัปขึ้น `main`

## คะแนนของตัวหลัก

| งาน | วัดด้วย | คะแนนในเครื่อง | วิธีวัด | คำสั่ง |
|---|---|---|---|---|
| 1 | Macro F2 | 0.777 | OOF 3 fold, threshold 0.385 | `python Task1/train.py --folds 3` |
| 2 | Macro F1 | 0.752 | OOF 3 fold | `python Task2/train.py --folds 3` |
| 3 | 1/(1+NMAE) | 0.775 | OOF 3 fold | `python Task3/train.py --folds 3` |
| 4 | Macro F1 | 0.913 | holdout 20% | `python Task4/train.py --epochs 5 --batch-size 128` |
| 5 | Macro F3 | วัดในเครื่องไม่ได้ | ไม่มี label | `python Task5/train.py --contamination 0.20` |

คะแนนของแต่ละงานหลังรันอยู่ใน `outputs/main/taskN_metrics.json`

## เตรียมข้อมูล

1. ดาวน์โหลดข้อมูลจากหน้า Data ของ Kaggle ใหม่ (ชุดหลังวันที่ 12 พ.ย.) แตกไว้ที่ `../cpe342-kaggle-main` ข้างโฟลเดอร์ repo นี้
2. ภาพของงาน 4 ดาวน์โหลดจาก Google Drive ด้วย `python prepare_images.py --download` ถ้ามี zip เก่าก่อนวันที่ 12 พ.ย. อยู่ ให้ลบแล้วโหลดใหม่ เพราะ `test.csv` ข้างในถูกแก้

ข้อมูลและไฟล์ผลลัพธ์ไม่ได้อยู่ใน repo (`.gitignore` กันไว้) แต่ละคนต้องมีข้อมูลในเครื่องตัวเอง

## ทำงานของตัวเองแล้วเทียบยังไง

1. รันงานที่รับผิดชอบด้วยคำสั่งในตาราง จดคะแนนก่อนแก้
2. แก้โค้ด แล้วรันคำสั่งเดิมด้วย `--folds` และ `--seed` เดิม คะแนนจะเทียบกันได้เพราะแบ่ง fold ชุดเดียวกัน
3. ถ้าคะแนนดีขึ้นน้อยกว่าความต่างระหว่าง fold (ดู `fold_scores` ในไฟล์ metrics) ให้ถือว่ายังไม่ดีขึ้นจริง
4. รัน `python -m pytest -q tests` ให้ผ่านก่อนอัป
5. ตอน commit เขียนในข้อความว่างานไหน เปลี่ยนอะไร และคะแนนก่อนกับหลังเป็นเท่าไร

งาน 5 ไม่มีคะแนนในเครื่อง การเปลี่ยนแปลงของงานนี้ต้องตกลงกันในทีมก่อนว่าจะใช้โควตาส่ง Kaggle เมื่อไร

## รวมไฟล์ส่ง

ต้องมี `taskN_predictions.csv` ครบ 5 งานในโฟลเดอร์ผลลัพธ์เดียวกัน คนที่รันแค่งานเดียวให้ขอไฟล์คำทำนายของงานอื่นจากเพื่อนผ่านช่องทางส่วนตัวของทีม ไม่อัปขึ้น repo

```
python run.py assemble
python run.py validate
```
