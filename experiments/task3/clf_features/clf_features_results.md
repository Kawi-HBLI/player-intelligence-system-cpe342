## Interpretation

- **ผลเป็นลบ: ไม่มี feature กลุ่มไหนยก AUC ของ classifier ได้ถึงเกณฑ์** ทุก config อยู่ในช่วง 0.7843–0.7845 เทียบกับ V4 0.7841 (Δ OOF AUC สูงสุด +0.0003 จากเกณฑ์ +0.002) จึงหยุดที่ step 2 ไม่สร้าง V5 และไม่มีไฟล์ Kaggle ใหม่ champion ยังเป็น V4 และไฟล์ส่งยังเป็น V4 refit (public LB 0.80371)
- **กลุ่มที่ผ่านกฎ "ชนะทุก fold" มีแค่ timing** (+0.0004 / +0.0000 / +0.0005) แต่ fold 2 แทบไม่เปลี่ยน (+0.0000 เมื่อปัด 4 ตำแหน่ง) ส่วน all-in ก็ชนะทุก fold แต่ได้ +0.0003 เท่ากัน activity, spend_habit, zero_rate แพ้อย่างน้อย 1 fold และขนาดของ Δ ต่อ fold (−0.0007 ถึง +0.0008) เล็กมาก และใน fold เดียวกัน early stopping หยุดต่างกันได้ 60–90 รอบระหว่าง config (เช่น fold 3: 153–241) จึงถือว่าความต่างระดับนี้แยกจาก noise ไม่ได้
- **`group_zero_rate` ขึ้นอันดับ 1 ของ importance (21.77) แต่ไม่เพิ่ม AUC** เพราะมันแทนที่ข้อมูลเดิม ไม่ได้เพิ่มข้อมูลใหม่: ใน V4 reference `segment` มี importance 26.00 และ `vip_status` 4.23 พอเพิ่ม zero rate เหลือ 10.98 และ 1.81 คือโมเดลแค่ย้ายจากการ split สองคอลัมน์ไปใช้คอลัมน์ที่สรุปไว้แล้ว ดังนั้น importance สูงไม่ได้แปลว่า feature ช่วย ต้องดูที่ AUC
- **feature ด้าน timing / activity / spend habit อยู่อันดับ 11–48** (สูงสุดคือ `recency_bucket` อันดับ 11) ทั้งหมดสร้างจากคอลัมน์ที่โมเดลมีอยู่แล้ว (ratio, product, rank, bucket) และ CatBoost depth 6 ประมาณความสัมพันธ์เหล่านี้ได้เองจากการ split ต่อกัน จึงได้เพิ่มน้อย
- **ข้อสรุปเมื่อรวมกับ V3b:** โมเดลใหญ่ขึ้นไม่ช่วย (0.7841 → 0.7842) และ feature ใหม่ 12 ตัวจาก 4 แนวคิดก็ไม่ช่วย (สูงสุด 0.7845) แสดงว่าข้อมูล "จะใช้เงินไหม" ที่ดึงได้จาก 32 คอลัมน์นี้ถูกใช้ไปเกือบหมดแล้ว ส่วนที่เหลือของ AUC น่าจะเป็นความสุ่มของพฤติกรรมที่คอลัมน์เหล่านี้ไม่ได้บันทึก (ยังไม่ได้พิสูจน์ เป็นการอนุมานจากผลสองชุดนี้)
- **ทำต่อ:** ไม่ควรลงแรงกับ classifier ต่อ oracle test เคยแสดงว่าถ้ารู้ยอดจริง (zero จาก baseline) จะได้ +0.148 แต่ถ้ารู้ zero จริง (ยอดจาก baseline) ได้แค่ +0.054 (`oracle/oracle_results.md`) ขั้น "ใช้เท่าไร" จึงยังมีที่ให้ปรับมากกว่า
