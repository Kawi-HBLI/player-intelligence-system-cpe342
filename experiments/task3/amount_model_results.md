## Interpretation

> **NOTE:** ทุกแถวใช้ early stopping บน validation fold เหมือน baseline คะแนนจึงสูงเกินจริงเล็กน้อยเท่ากันทุกแถว แต่เทียบกันได้

- **V3 ดีสุด: OOF 0.7900 (+0.0147) และชนะ baseline ทุก fold** (0.7958 / 0.7823 / 0.7923 เทียบกับ 0.7873 / 0.7587 / 0.7807) ส่วน V2 ได้ 0.7849 (+0.0096) ก็ชนะทุก fold เช่นกัน threshold ที่จูนบน OOF ออกมาเป็น 0.500 ทั้งสองตัว ตรงกับ median rule ตามทฤษฎี จึงไม่มีความ optimistic เพิ่มจากการจูน threshold
- **error ของกลุ่ม >20k ลดลงจริง:** จาก 199.8M เหลือ 173.4M บาท (−13%) และกลุ่ม 1k–20k จาก 20.5M เหลือ 15.3M ดูเฉพาะคนที่ใช้เงิน (y > 0) regressor ของ V3 ได้ 0.8540 เทียบกับ V2 0.8480 และ baseline 0.8290 แปลว่าการทาย `log(y / prev)` ด้วย MAE ดีกว่าทายยอดเป็นบาทตรงๆ
- **แต่ bucket 0 แย่ลง:** จาก 91.2M เป็น 96.9M บาท เพราะ classifier มี OOF AUC แค่ 0.7841 คะแนนที่ได้เพิ่มทั้งหมดจึงมาจากขั้น "ใช้เท่าไร" ขั้น "ใช้เงินไหม" ยังเป็นจุดที่ต้องปรับต่อ
- **V1 (ใส่ feature ใหม่ใน single-stage) แย่ลง −0.0074 (0.7679)** แพ้ baseline 2 ใน 3 fold (ชนะแค่ fold 2) เราตรวจแยกด้วยโค้ดเดียวกัน (รันครั้งเดียว ไม่ได้อยู่ในตารางข้างบน): ไม่ใส่ feature ใหม่ได้ 0.7753 เท่ากับ baseline ทุก fold ส่วนใส่ `expected_spend` ตัวเดียวได้ 0.7710 แปลว่า feature นี้ไม่ช่วยโมเดลที่ต้องทายทั้ง zero และยอดพร้อมกัน แต่ช่วยเมื่อแยกเป็น two-stage ยังไม่ได้พิสูจน์ว่าทำไม
- **ทำต่อ:** regressor ของ V2/V3 หยุดที่ 972–1000 รอบ (ชนเพดาน 1000) อาจได้เพิ่มถ้าเทรนนานขึ้น ส่วน classifier หยุดเร็ว (120–214 รอบ) งานถัดไปคือปรับ classifier เพื่อลด error 96.9M ของ bucket 0 แล้วค่อยส่ง V3 (`outputs/experiments/task3_v3/task3_predictions.csv`) ขึ้น Kaggle เพื่อดู LB
