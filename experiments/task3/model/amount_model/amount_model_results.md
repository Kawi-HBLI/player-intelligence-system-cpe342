## Interpretation

> **NOTE:** ทุกแถวใช้ early stopping บน validation fold เหมือน baseline คะแนนจึงสูงเกินจริงเล็กน้อยเท่ากันทุกแถว แต่เทียบกันได้

### V1–V3 (step 7)

- **V3 ดีสุด: OOF 0.7900 (+0.0147) และชนะ baseline ทุก fold** (0.7958 / 0.7823 / 0.7923 เทียบกับ 0.7873 / 0.7587 / 0.7807) ส่วน V2 ได้ 0.7849 (+0.0096) ก็ชนะทุก fold เช่นกัน threshold ที่จูนบน OOF ออกมาเป็น 0.500 ทั้งสองตัว ตรงกับ median rule ตามทฤษฎี จึงไม่มีความ optimistic เพิ่มจากการจูน threshold
- **error ของกลุ่ม >20k ลดลงจริง:** จาก 199.8M เหลือ 173.4M บาท (−13%) และกลุ่ม 1k–20k จาก 20.5M เหลือ 15.3M ดูเฉพาะคนที่ใช้เงิน (y > 0) regressor ของ V3 ได้ 0.8540 เทียบกับ V2 0.8480 และ baseline 0.8290 แปลว่าการทาย `log(y / prev)` ด้วย MAE ดีกว่าทายยอดเป็นบาทตรงๆ
- **แต่ bucket 0 แย่ลง:** จาก 91.2M เป็น 96.9M บาท เพราะ classifier มี OOF AUC แค่ 0.7841 คะแนนที่ได้เพิ่มทั้งหมดจึงมาจากขั้น "ใช้เท่าไร" ขั้น "ใช้เงินไหม" ยังเป็นจุดที่ต้องปรับต่อ
- **V1 (ใส่ feature ใหม่ใน single-stage) แย่ลง −0.0074 (0.7679)** แพ้ baseline 2 ใน 3 fold (ชนะแค่ fold 2) เราตรวจแยกด้วยโค้ดเดียวกัน (รันครั้งเดียว ไม่ได้อยู่ในตารางข้างบน): ไม่ใส่ feature ใหม่ได้ 0.7753 เท่ากับ baseline ทุก fold ส่วนใส่ `expected_spend` ตัวเดียวได้ 0.7710 แปลว่า feature นี้ไม่ช่วยโมเดลที่ต้องทายทั้ง zero และยอดพร้อมกัน แต่ช่วยเมื่อแยกเป็น two-stage ยังไม่ได้พิสูจน์ว่าทำไม
- V3 จึงเป็น champion ตัวแรก (`experiments/task3/model/champion/`)

### V3a / V3b (step 8)

- **champion ไม่เปลี่ยน:** V3a และ V3b ได้ OOF 0.7901 (+0.0001 จาก V3) แต่แพ้ V3 ที่ fold 3 ทั้งคู่ ค่าต่างต่อ fold (คำนวณจากไฟล์ OOF ไม่ได้อยู่ในตาราง) คือ V3a +0.00022 / +0.00006 / −0.00008 และ V3b +0.00021 / +0.00008 / −0.00006 ต่างกันน้อยกว่าความต่างระหว่าง fold มาก
- **V3a: เพิ่มเพดานเป็น 3000 รอบ ไม่ช่วย** regressor หยุดเองที่ 1205–1337 รอบ (เพดาน 1000 ของ V3 ตัดก่อนจริง) แต่คะแนนบนคนที่ใช้เงินยังเป็น 0.8540 เท่า V3 รอบที่เกินมาจึงแทบไม่ได้อะไร
- **V3b: classifier ลึกขึ้นไม่ช่วย** AUC จาก 0.7841 เป็น 0.7842 หยุดที่ 175–206 รอบ ใกล้กับตัวเดิม (120–214) error ของ bucket 0 ยังเป็น 96.9M (V3 96,892,963 → V3b 96,885,767 บาท ลดแค่ 7k) แปลว่าขีดจำกัดของขั้น "ใช้เงินไหม" ไม่ได้อยู่ที่ขนาดโมเดล แต่น่าจะอยู่ที่ข้อมูลหรือ feature
- **ทำต่อ:** ปรับ hyperparameter ของ V3 ต่อน่าจะได้น้อย ขั้นที่น่าลองคือ feature ใหม่สำหรับ classifier หรือแก้กฎ combine ให้ใช้ quantile (1 − 0.5/p) ของยอดแทน median ตามที่เขียนไว้ใน comment ของ script แล้วค่อยส่ง champion ขึ้น Kaggle เพื่อดู LB

### V4 quantile combine (step 9)

- **V4 ชนะ V3 ทุก fold จึงเป็น champion ใหม่:** OOF 0.7918 (+0.0018 จาก V3, +0.0165 จาก baseline) ต่อ fold +0.0024 / +0.0018 / +0.0011 ใช้ classifier ตัวเดียวกับ V3 (AUC 0.7841 เท่ากัน) แต่ขั้นยอดใช้ CatBoost `MultiQuantile` (α = 0.05–0.5) บน `log(y / prev)` แล้วให้ยอดเป็น quantile ที่ q = 1 − 0.5/p ตามสูตรใน comment ของ script ส่วน CatBoost 1.2.10 รองรับ MultiQuantile จึงไม่ต้องแยกโมเดลทีละ alpha
- **sanity check (V4-median):** ใช้แค่คอลัมน์ α = 0.5 กับ threshold 0.5 แบบ V3 ได้ 0.7905 ใกล้ V3 ตามที่คาด แต่สูงกว่า V3 เล็กน้อย (+0.0005) และชนะทุก fold ด้วย โมเดล quantile ทาย median ได้ดีพอๆ กับ MAE (คะแนนบนคนที่ใช้เงิน 0.8541 เทียบกับ 0.8540) ดังนั้นจาก +0.0018 ของ V4 ประมาณ +0.0005 มาจากตัวโมเดลยอด และประมาณ +0.0013 มาจากกฎ quantile
- **bucket 0 ลดลงตามเป้า:** error จาก 96.9M เหลือ 92.1M บาท (−4.8M, −5.0%) ใกล้ baseline (91.2M) แต่ต้องจ่ายคืนบางส่วน กลุ่ม 1k–20k เพิ่ม +1.1M (+6.9%) และ >20k เพิ่ม +0.7M (+0.4%) รวมแล้ว error ลด 3.1M (−1.1%) ส่วนที่ได้จากกลุ่ม >20k ยังอยู่เกือบทั้งหมด (baseline 199.8M → V4 174.0M)
- **p ของ classifier calibrate ดีในช่วงที่ใช้งาน:** ช่วง p 0.5–1.0 ค่าเฉลี่ย p ต่างจากสัดส่วนคนที่ใช้เงินจริงไม่เกิน 0.011 ส่วน V4s ที่ scan s = 0.6–1.4 ได้ค่าดีสุดที่ s = 1.0 พอดี (0.7918) ถ้า s > 1 คะแนนตกเร็ว (s = 1.4 ได้ 0.7821) จึงไม่มีสัญญาณว่า p มี bias ที่ควรแก้ ช่วงที่ calibrate แย่สุดคือ p 0.3–0.4 (p ต่ำไป 0.028) ซึ่งอยู่ฝั่งที่ทายเป็น 0 อยู่แล้ว
- **quantile ล่างของโมเดลยังสูงไป:** coverage บนคนที่ใช้เงินของ α = 0.05 คือ 0.075 และ α = 0.10 คือ 0.127 (ควรเท่า α) ส่วน α ≥ 0.35 ใกล้เคียง α แถวที่ quantile ไขว้กันมี 3.5% (เรียงใหม่ก่อนใช้) ตอนรัน --quick (250 รอบ) coverage ตรงกว่านี้ แสดงว่า early stopping ที่ดู loss เฉลี่ยทุก α อาจไม่เหมาะกับ α ต่ำ ยังไม่ได้ทดสอบ
- **ทำต่อ:** ส่ง V4 ขึ้น Kaggle ด้วย `make_submission.py` บนไฟล์ฐานเดิม (0.80097) เพื่อเทียบกับ V3 (0.80313) ได้ตรงๆ ถ้าจะปรับต่อ ลองแก้ quantile ล่าง (โมเดลแยกต่อ α หรือปรับ quantile ด้วย OOF) หรือเพิ่ม feature ให้ classifier
