## Interpretation

### Result

- **ผลเป็นลบ: ไม่มี variant ไหนชนะ V4 ครบ 3 fold** ทั้งสามแพ้ fold 3 (V7a −0.00036, V7b −0.00029, V7 −0.00029) OOF ดีขึ้นแค่ +0.0001 (0.7919 vs 0.7918) จึงหยุดตามกฎ: ไม่ promote, ไม่ refit, ไม่สร้างไฟล์ Kaggle, champion ยังเป็น V4 และไฟล์ส่งยังเป็น V4 refit (public LB 0.80371)
- **V4 re-run ตรงกับ champion ทุก fold** (0.7982 / 0.7841 / 0.7934) การเทียบจึงใช้ได้

### Why calibration did not help

- **Coverage แก้ได้ตามที่ตั้งใจ (ช่วง α ≥ 0.05):** model 14 alphas ดิบได้ coverage 0.076 ที่ α=0.05 และ 0.128 ที่ 0.10 (ใกล้ V4 0.075 / 0.127) หลัง remap ได้ 0.048 / 0.097 และใกล้ alpha ทุกระดับจนถึง 0.45 map เกือบเหมือนกันทั้ง 3 fold (α'(0.05) = 0.0259 / 0.0260 / 0.0257) แปลว่า bias นี้เป็นระบบ ไม่ใช่ noise
- **ต่ำกว่า 0.05 แก้ไม่ได้:** quantile ที่ α=0.01 ยังมี coverage 0.029 จึงอ่านค่าต่ำกว่านั้นไม่ได้ (map ถูก clamp ที่ 0.01) coverage หลัง calibrate ของ α 0.01–0.03 จึงค้างที่ 0.029–0.030 ส่วน α=0.5 ต้องการ α' > 0.5 ซึ่งไม่ได้ model ไว้ จึงค้างที่ 0.492
- **bucket 0 ดีขึ้นจริงแต่ spender จ่ายคืน:** V7b ลด error ของ bucket 0 −0.21M (V7 −0.24M) แต่ 1k-20k เพิ่ม +0.26M (+0.29M) รวมทั้งหมด −0.11M จาก 287M (−0.04%) ที่ L1 การลด quantile คือการย้าย error จากแถว y = 0 ไปแถว spender; จะได้กำไรสุทธิก็ต่อเมื่อ quantile เดิมผิด**สำหรับแถวที่ p ใกล้ 0.5** ส่วน coverage ที่วัดได้เป็นค่าเฉลี่ยของ spender ทุกคน (marginal) ผลที่ได้บอกว่าแถวที่ได้ q ต่ำไม่ได้ over-cover มากเท่าค่าเฉลี่ย (อนุมานจากผลรวม ไม่ได้วัด coverage แยกตาม p โดยตรง)
- **แถวที่ clip 0.05 กระทบมีน้อย:** แถว OOF ที่ 0.5 < p < 0.526 มี 1,882 แถว (3.6% ของ 51,638 แถวที่ได้ยอด) และ 45.6% ของแถวกลุ่มนี้เป็น y = 0 การลด clip จึงแทบไม่เปลี่ยนคะแนน (−0.00001)
