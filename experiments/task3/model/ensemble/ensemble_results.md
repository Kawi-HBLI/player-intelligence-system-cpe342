# Task 3 V6 / V6x: ensembled amount model

> **CAUTION:** Early stopping uses the validation fold (as in the baseline and V4) for every amount model, so every OOF score here is slightly optimistic; differences between rows are still comparable. V6w / V6xw pick w on the same OOF they are scored on.

Generated by `python experiments/task3/model/ensemble/ensemble.py --promote`. Folds `KFold(3, shuffle=True, random_state=342)`; metric `_score` from `pis/tabular.py`. Classifier, features, `expected_spend` rule, target `log(y / prev)` + `prev_missing` and `quantile_combine` (s = 1, t = 0.5) are imported from `amount_model.py` unchanged (V4 re-run here: 0.7982 / 0.7841 / 0.7934, reproduces the champion). Both second learners use the same spender rows, target and features as V4's amount model, categoricals as pandas `category`, and early-stop on the validation fold's spenders with the quantile loss.

- **LightGBM (V6):** one `LGBMRegressor(objective='quantile', alpha=a)` per alpha in 0.05…0.50 (num_leaves 63, lr 0.05, ≤ 3000 trees, early stopping 100, min_child_samples 50, subsample 0.8 / freq 1, colsample_bytree 0.8, seed 342 + fold).
- **XGBoost (V6x):** one `XGBRegressor(objective='reg:quantileerror', quantile_alpha=ALPHAS)` for all alphas (`tree_method='hist'`, `enable_categorical=True`, max_depth 6, lr 0.05, ≤ 3000 trees, early stopping 100, subsample 0.8, colsample_bytree 0.8, min_child_weight 5, seed 342 + fold).

Blend per alpha on the log-ratio scale: `log_q = w · CatBoost + (1 − w) · other`, then sorted per row and combined as in V4. V6 / V6x: w = 0.5 fixed in advance (promotion candidates); V6w / V6xw: best w on the OOF grid 0.0–1.0 step 0.1; w = 0 rows show each learner alone.

**Decision: STOP: V6 does not beat V4 on all 3 folds (Δ per fold -0.00117 / -0.00116 / -0.00117); STOP: V6x does not beat V4 on all 3 folds (Δ per fold -0.00065 / -0.00068 / -0.00081); champion stays V4, no refit, no Kaggle file.**

## Interpretation

### LightGBM (V6)

- **ผลเป็นลบ: V6 แพ้ V4 ทุก fold และแพ้เท่ากันทุก fold** (−0.00117 / −0.00116 / −0.00117, OOF 0.7906 vs 0.7918) ความต่างสม่ำเสมอขนาดนี้ไม่ใช่ noise จึงหยุดตามกฎ time budget: ไม่ refit, ไม่สร้างไฟล์ Kaggle, champion ยังเป็น V4 และไฟล์ส่งยังเป็น V4 refit (public LB 0.80371)
- **สาเหตุหลัก: LightGBM เป็น amount model ที่อ่อนกว่า CatBoost ชัดเจน** บนแถว spender คอลัมน์ α=0.5 ได้ 0.8462 vs CatBoost 0.8541 (−0.0079) และ LightGBM alone (w=0) แพ้ V4 −0.0059 การเฉลี่ยสองโมเดลจะได้กำไรเมื่อความแม่นใกล้กันและผิดคนละแบบ แต่ที่นี่ blend (0.8526) อยู่ระหว่างสองโมเดลและต่ำกว่า CatBoost จึงไม่มี "diversity bonus" มากพอจะชดเชยช่องว่างความแม่น
- **แม้เลือก w บน OOF เองก็ไม่ได้อะไร** OOF เพิ่มขึ้นทางเดียวจาก w=0 (0.7859) ถึง w=0.8 แล้วแบนที่ 0.7918 ถึง w=1.0; w ที่ดีที่สุด 0.9 ได้ +0.00012 / −0.00000 / +0.00001 เทียบ V4 คือเท่ากับ V4 แม้จะเป็นตัวเลขที่มองโลกในแง่ดีอยู่แล้ว แปลว่า LightGBM ไม่มีข้อมูลที่ CatBoost ยังไม่มี
- **แยกตาม bucket:** V6 แย่ลงที่ bucket 0 (+0.56M, +0.6%) และ >20k (+1.63M, +0.9%) ดีขึ้นเล็กน้อยที่ 1k-20k (−0.15M) และ >0-1k (−0.01M) error ของ bucket 0 มาจากแถวที่ p > 0.5 แต่ y = 0 ซึ่งได้ยอดจาก quantile ต่ำ (q ใกล้ 0.05)
- **Coverage อธิบาย bucket 0:** coverage > alpha แปลว่า quantile ที่ทำนายสูงเกินไป LightGBM สูงเกินทุก alpha (0.094 ที่ α=0.05 ถึง 0.535 ที่ α=0.5) ส่วน CatBoost สูงเกินที่ alpha ต่ำ (0.075 ที่ 0.05) และต่ำนิดหน่อยที่ 0.5 (0.489) blend จึงดัน quantile ต่ำให้สูงขึ้นอีก (0.082 ที่ 0.05) ยอดของ spender ที่ไม่แน่ใจจึงสูงขึ้น ซึ่งสอดคล้องกับ bucket 0 ที่แย่ลง (เป็นการอนุมานจากสองตาราง ไม่ได้แยกวัดตรง ๆ) ส่วนที่ α=0.5 blend ได้ coverage 0.503 ใกล้ 0.5 กว่า CatBoost แต่คะแนนกลับแย่กว่า: calibration ดีไม่ได้แปลว่า error ต่อแถวต่ำ
- **Crossing:** LightGBM แยก 10 โมเดลต่อ alpha จึงไขว้กัน 95.5% ของแถว (CatBoost MultiQuantile โมเดลเดียว 3.5%) ทุกแถวถูก sort ก่อนใช้ จึงไม่ใช่สาเหตุของคะแนน แต่เป็นอีกเหตุผลที่โมเดลแยกต่อ alpha หยาบกว่า
- **Runtime:** LightGBM 10 alphas ใช้ 102s ต่อ 3 fold เทียบ CatBoost MultiQuantile 118s (run แรกที่มีแค่ LightGBM: 81s / 107s เวลาแกว่งตามภาระเครื่อง แต่ score ตรงกันทุกหลัก)
- **ข้อจำกัด:** LightGBM ใช้ค่า default ตามแผน ไม่ได้ tune (ตามกฎ time budget) LightGBM ที่ tune แล้วอาจปิดช่องว่างได้บ้าง แต่ช่องว่าง −0.0079 บนแถว spender ใหญ่กว่าที่การ tune ทั่วไปมักให้ (ยังไม่ได้พิสูจน์)
### XGBoost (V6x)

- **ผลเป็นลบเช่นกัน: V6x แพ้ V4 ทุก fold** (−0.00065 / −0.00068 / −0.00081, OOF 0.7911 vs 0.7918) แพ้น้อยกว่า V6 (−0.0012) แต่ยังแพ้สม่ำเสมอทุก fold จึงหยุดตามกฎ: ไม่ refit ไม่มีไฟล์ Kaggle และไม่ tune XGBoost ต่อ
- **XGBoost ดีกว่า LightGBM แต่ยังห่าง CatBoost มาก** บนแถว spender คอลัมน์ α=0.5 ได้ 0.8474 (LightGBM 0.8462, CatBoost 0.8541 คือ −0.0067) XGBoost alone แพ้ V4 −0.0046 (LightGBM alone −0.0059) blend 0.5 ได้ 0.8530 อยู่ระหว่างสองโมเดลและต่ำกว่า CatBoost เหมือน V6
- **V6xw (w=0.9) ชนะ V4 ทุก fold แต่ไม่นับ:** +0.00013 / +0.00003 / +0.00002 (OOF +0.0001) w ถูกเลือกบน OOF ชุดเดียวกับที่ใช้วัด จึงเป็นตัวเลขที่มองโลกในแง่ดี และขนาดเล็กกว่าความต่างที่ early stopping ทำให้เกิดได้เองระหว่าง run อยู่มาก ตามกฎ champion มีแค่ V6 / V6x (w=0.5 กำหนดล่วงหน้า) ที่มีสิทธิ์ promote
- **แยกตาม bucket ได้รูปเดียวกับ V6 แต่เล็กกว่า:** V6x แย่ลงที่ bucket 0 (+0.32M, +0.4%) และ >20k (+1.06M, +0.6%) ดีขึ้นเล็กน้อยที่ 1k-20k (−0.13M) และ >0-1k (−0.01M) รวม +1.24M (+0.4%) เทียบ V6 +2.04M
- **Coverage:** XGBoost สูงเกินที่ alpha กลางถึงสูง (0.417 ที่ 0.40, 0.535 ที่ 0.50) และที่ alpha ต่ำสูงเกินน้อยกว่า LightGBM (0.082 vs 0.094 ที่ 0.05) blend V6x จึงใกล้ CatBoost ที่ quantile ต่ำ (0.076 vs 0.075 ที่ 0.05) สอดคล้องกับ bucket 0 ที่เสียน้อยกว่า V6 (อนุมานจากสองตาราง ไม่ได้แยกวัดตรง ๆ)
- **Crossing 91.8% ทั้งที่เป็นโมเดลเดียว:** quantile ไขว้กันเกือบเท่า LightGBM ที่แยก 10 โมเดล (95.5%) ส่วน CatBoost MultiQuantile ไขว้แค่ 3.5% แสดงว่า XGBoost ไม่ได้ผูก alpha เข้าด้วยกันแบบที่ CatBoost ทำ (ค่า default `multi_strategy` ของ XGBoost สร้าง tree แยกต่อ output) ทุกแถวถูก sort ก่อนใช้ จึงไม่ใช่สาเหตุโดยตรงของคะแนน
- **Runtime:** XGBoost ช้าที่สุด 223s ต่อ 3 fold (94 / 64 / 65s) เทียบ CatBoost 118s และ LightGBM 102s ทั้ง run 453s
- **ข้อสรุปรวม:** GBDT สองตระกูลที่ต่างจาก CatBoost ให้ผลแบบเดียวกัน คืออ่อนกว่าบน amount target นี้ และ blend ได้แค่ค่าระหว่างกลาง ไม่มี diversity bonus การเพิ่ม learner บน feature ชุดเดิมจึงน่าจะหมดทางแล้ว เหตุที่ CatBoost นำอาจมาจากวิธีจัดการ categorical (ordered target statistics) แต่ยังไม่ได้ทดสอบ
