## Interpretation

> **NOTE:** ตัวเลขทั้งหมดเป็น upper bound จาก oracle ไม่ใช่คะแนนที่ submit ได้ classifier/regressor จริงจะได้ต่ำกว่านี้

- **ถ้าขั้น "ใช้เงินไหม" สมบูรณ์ (B) ได้ +0.0537** (0.7753 → 0.8290) เพราะ error ของคนที่ target = 0 คิดเป็น 28.8% ของ error baseline (91.2M บาท) จึงคุ้มที่จะทำ classifier แต่ไม่ใช่คอขวดหลัก
- **ถ้าขั้น "ใช้เท่าไร" สมบูรณ์ (E) ได้ +0.1476** (→ 0.9229) มากกว่า B ประมาณ 2.7 เท่า ใน B error ที่เหลือ 88.7% มาจาก bucket >20k (199.8M บาท จาก 12,853 คน) ดังนั้นคอขวดหลักคือการทายยอดของคนที่ใช้เงินเยอะ
- **กฎ ratio แบบง่ายยังไม่พอ:** แม้รู้ zero ถูกหมด C (ratio ตาม segment) ได้ 0.7599 ต่ำกว่า baseline (−0.0154) ส่วน D (segment × VIP) ได้ 0.7900 (+0.0146) ยังห่างจาก B (0.8290) มาก error bucket >20k ของ C คือ 315.1M เทียบกับ 199.8M ของ baseline amount ใน B
- **สรุปลำดับงาน:** เน้นขั้น "ใช้เท่าไร" ก่อน โดยเฉพาะกลุ่ม >20k ใช้ model จริง (เช่น regressor บนคนที่ใช้เงิน) แทนกฎ ratio โดยเอา `prev_month_spending × ratio ของ segment/VIP` เป็น feature ได้ ส่วน classifier "ใช้เงินไหม" เป็นงานลำดับถัดไป
