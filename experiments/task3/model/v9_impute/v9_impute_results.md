# Task 3 V9: label-free imputation of the spend-history features

Generated by `python experiments/task3/model/v9_impute/v9_impute.py --threads 12 --promote`. Protocol honest-es, same folds, fit/es split, classifier recipe, amount settings (`tuning/v8.json`), quantile combine and cap as V8. Imputer: one `HistGradientBoostingRegressor(random_state=342)` per feature on `log1p(feature)` from the other raw features (never `spending_30d`), fitted inside each outer fold on the outer-training rows only and applied to the outer-training, validation and test rows; only missing values are replaced (clipped to the observed range). Every downstream piece reads the imputed frame: model features, the `expected_spend` family, the log-ratio target (so the imputed prev is the denominator only where prev was missing) and the prev that turns quantiles back into THB (test: geometric mean of the 3 fold imputers). Both stages get the original missing flags (`prev_missing`, and in V9b `historical_spending_missing`, `avg_transaction_value_missing`); the classifier is refitted on these inputs with V4's recipe. V8 is re-run in the same script and matches `v8.json` within 0.0001 in both seed runs.

> **NOTE:** Rule fixed before the run: a variant is eligible only if it beats V8 on all 3 folds with BOTH amount seed schemes (342 + fold and 1342 + fold); if both are eligible, V9b is chosen only if its OOF beats V9a by more than 0.0003.

**Decision: V9A beats V8 on all 3 folds in both seed runs (eligible: V9A, V9B; chosen: V9A). Per fold vs V8: V9A seed 342: +0.0032 / +0.0024 / +0.0021; V9A seed 1342: +0.0036 / +0.0025 / +0.0020; V9B seed 342: +0.0033 / +0.0027 / +0.0022; V9B seed 1342: +0.0036 / +0.0027 / +0.0020.** **Promoted.**

## Interpretation

- **ผล:** V9a และ V9b ชนะ V8 ทุก fold ทั้งสอง seed scheme (+0.0020 ถึง +0.0036 ต่อ fold) V9a ได้ OOF 0.7947 (+0.0026) V9b ดีกว่า V9a แค่ +0.0002 ต่ำกว่าเกณฑ์ 0.0003 ที่ตั้งไว้ก่อนรัน จึงเลือก **V9a** (เติมแค่ `prev_month_spending` ตัวเดียว ง่ายกว่า) และ promote เป็น champion
- **มาจากไหน:** เกือบทั้งหมดมาจากแถวที่ `prev_month_spending` หาย (0.758 → 0.798, +0.040) ส่วนแถวที่มี prev แทบไม่เปลี่ยน (+0.0001) ตรงกับสมมติฐานใน `missing_eda.ipynb`: V8 ต้องทาย `log(y)` ตรงๆ จากแค่ ~6% ของแถว พอเติม prev แล้วแถวพวกนี้ใช้ target `log(y / prev)` แบบเดียวกับคนอื่น error ของคนที่ใช้เงินในกลุ่มนี้ลดจาก 16.4M เหลือ 11.6M บาท ส่วน error ของแถว y = 0 เพิ่มนิดหน่อย (+0.6M) เพราะทาย 0 น้อยลง (สัดส่วนที่ทาย 0 จาก 0.531 เหลือ 0.506 เท่ากับกลุ่มที่มี prev 0.505) ดูตาม bucket: >20k ลด 4.2M, 1k–20k ลด 0.8M, bucket 0 เพิ่ม 0.5M
- **ทำไมเกินขอบบน oracle (+0.0022) ใน EDA:** oracle สมมติว่ากลุ่มที่ prev หายดีได้แค่เท่ากลุ่มที่มี prev แต่ V9a ทำให้กลุ่มที่หาย (0.798) ดีกว่ากลุ่มที่มี prev (0.7945) เพราะ prev ที่เติมมาจาก `historical_spending` เป็นหลัก ซึ่งสัมพันธ์กับยอดเดือนหน้าพอๆ กับ prev จริง (Spearman ในกลุ่มที่ใช้เงิน 0.977 เทียบกับ 0.976) จึงเป็นตัวหารที่ดีพอกัน ไม่ใช่ leakage: imputer ไม่เคยเห็น `spending_30d` และ fit บนแถว outer-train เท่านั้น (ไม่เห็นแถว validation หรือ test)
- **แถวที่หายหลายช่อง:** กลุ่มที่หาย 2+ ช่องดีขึ้น +0.0043 ส่วนใหญ่เพราะแถวที่ prev หายอยู่ในกลุ่มนี้ กลุ่ม 0–1 ช่องแทบไม่เปลี่ยน (+0.0004)
- **V9b:** เติม `historical_spending` กับ `avg_transaction_value` เพิ่มแทบไม่ช่วย (+0.0001 ถึง +0.0003 เหนือ V9a) เพราะสองตัวนี้ไม่ได้เป็นตัวหารของ target และ CatBoost จัดการค่าว่างของมันได้อยู่แล้ว
- **Refit:** V9a refit ผ่านทั้ง 7 checks (fold-1 check 0.8020 เทียบกับ CV 0.8019, Spearman กับ CV 0.9967) imputer ของ refit fit บน train ทั้งหมดเท่านั้น ไฟล์ Kaggle สร้างบน `best_082343.csv` (คอลัมน์ task3 เดิมตรงกับ V8 refit) แต่ยังไม่ได้ส่ง

**CAUTION:** CV +0.0026 แต่ครั้งก่อน V8 ชนะ V4 ใน CV +0.0010 แล้วขึ้นบน Kaggle public แค่ +0.00008 ต้องดูผลจริงบน leaderboard ข้อดีครั้งนี้คือผลมาจากกลุ่มที่ชัดเจน และ test มีแถวที่ prev หาย 1,532 แถว (5.9%) ใกล้กับ train (5.8%) จึงน่าจะเห็นผลบน LB มากกว่า V8
