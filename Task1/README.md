# Task 1: Anti-Cheat Detection

จำแนกบัญชีที่ถูก flag ว่าเป็นคนโกงจริง (1) หรือผู้เล่นปกติ (0) วัดด้วย Macro F2

## ข้อมูล

- train 104,000 แถว มี label 90,816 แถว อีก 13,184 แถวไม่มี label จึงตัดออกจากการเทรน
- 31 ฟีเจอร์ตัวเลข ค่าว่างเฉลี่ย 11.6% ต่อคอลัมน์
- คนโกงคิดเป็น 35% ของแถวที่มี label

## สิ่งที่ EDA เจอ

ข้อมูลจำลองสุ่มค่าของแต่ละกลุ่มจากช่วงตายตัวที่ต่างกัน ค่าที่อยู่นอกช่วงของอีกกลุ่มจึงบอกคำตอบได้แน่นอน

| ฟีเจอร์ | ผู้เล่นปกติ | คนโกง |
|---|---|---|
| `crosshair_placement` | 0.82 ถึง 0.96 | 0.80 ถึง 0.94 |
| `reports_received` | 5 ถึง 29 | 4 ถึง 19 |
| `level` | 28 ถึง 100 | 25 ถึง 96 |
| `account_age_days` | 1 ถึง 1,500 | 15 ถึง 1,000 |
| `friend_network_size` | 0 ถึง 349 | 10 ถึง 269 |

- กฎจากช่วงเหล่านี้ครอบคลุมคนโกง 20% และผู้เล่นปกติ 40% ครึ่งหนึ่งของแถวที่เหลืออยู่ในช่วงที่ซ้อนทับกัน ซึ่งโมเดลแยกได้แค่ AUC 0.67
- ค่าว่างทำให้แย่ลง แถวที่ฟีเจอร์สำคัญ 6 ตัวครบได้ AUC 0.904 ถ้าหายไป 3 ตัวเหลือ 0.82
- ในกลุ่มผู้เล่นปกติ `account_age_days` สัมพันธ์กับ `reports_received` (-0.27) และ `kill_death_ratio` (-0.18) แต่ในกลุ่มคนโกงไม่สัมพันธ์กันเลย naive Bayes ที่มองแต่ละฟีเจอร์แยกกันจึงได้ AUC แค่ 0.844 เทียบกับ CatBoost 0.888

## วิธีทำ

- CatBoost (Logloss, depth 6, learning rate 0.05, สูงสุด 1,000 รอบ, early stopping 80 รอบ) ส่งค่าว่างเข้าโมเดลตรงๆ
- ฟีเจอร์เพิ่มจาก `pis/task1_features.py`:
  - ระยะห่างจากขอบของช่วงในตารางข้างบน และจำนวนกฎที่แถวนั้นเข้าเงื่อนไขแน่นอน
  - ค่าประมาณของ `account_age_days`, `friend_network_size`, `level_progression_speed`, `level`, `reports_received` สำหรับแถวที่ค่าว่าง ประมาณจากฟีเจอร์ตัวอื่นด้วย gradient boosting ที่ไม่ได้ใช้ label
- Stratified 3-fold แล้วเฉลี่ยความน่าจะเป็นของ 3 โมเดลบน test
- F2 ให้น้ำหนัก recall มากกว่า precision จึงเลือก threshold จากค่า OOF ให้ macro F2 สูงสุด

## ผลในเครื่อง

ทุกแถวใช้ fold ชุดเดียวกัน (StratifiedKFold 3, seed 342) รันซ้ำได้ด้วย `python Task1/experiments.py ../cpe342-kaggle-main`

| การทดลอง | AUC | Macro F2 ที่ 0.5 | Macro F2 ปรับ threshold |
|---|---|---|---|
| ตัวหลัก | 0.8883 | 0.7570 | 0.7775 |
| เพิ่มอัตราส่วน เช่น level ต่อวัน | 0.8879 | 0.7566 | 0.7758 |
| เพิ่มตัวบอกค่าว่าง | 0.8878 | 0.7567 | 0.7756 |
| ต้นไม้ลึกขึ้น (depth 8) | 0.8879 | 0.7575 | 0.7760 |
| learning rate 0.03 เทรน 3,000 รอบ | 0.8882 | 0.7578 | 0.7769 |
| เพิ่มค่าประมาณของค่าว่าง | 0.8908 | 0.7578 | 0.7792 |
| เพิ่มกฎจากช่วงค่า | 0.8918 | 0.7585 | 0.7804 |
| **กฎจากช่วงค่า + ค่าประมาณของค่าว่าง (ที่ใช้อยู่)** | **0.8926** | **0.7598** | **0.7807** |

ดีขึ้นจากตัวหลัก 0.003 บน Macro F2 และ 0.004 บน AUC ทั้ง 3 fold ดีขึ้นหรือเท่าเดิม ส่วนต่างเล็ก เพราะแถวที่ชัดเจนถูกจับได้เกือบหมดตั้งแต่ตัวหลักแล้ว คะแนนที่ threshold ปรับแล้วสูงกว่าความจริงเล็กน้อย เพราะใช้ OOF ชุดเดียวกันทั้งเลือก threshold และวัดผล

## การทดลองรอบ 2: ฝั่งโมเดล

ใช้ฟีเจอร์ชุดที่ใช้อยู่เป็นฐานและ fold ชุดเดิม รันซ้ำได้ด้วย `python Task1/experiments_round2.py ../cpe342-kaggle-main`

|---|---|---|

## เพดานของงานนี้

คะแนนขึ้นกับจำนวนค่าว่างในแถวมากกว่าตัวโมเดล

| จำนวนฟีเจอร์ที่ว่างในแถว | AUC (OOF) | จำนวนแถว |
|---|---|---|
| 0 | 0.918 | 1,607 |
| 2 | 0.910 | 14,880 |
| 4 | 0.889 | 19,335 |
| 6 | 0.876 | 8,080 |
| 8 | 0.847 | 1,434 |

แถวที่ข้อมูลครบทุกฟีเจอร์ยังได้ AUC แค่ 0.918 ส่วนที่เหลือจึงเป็นการซ้อนทับของสองกลุ่มที่ข้อมูลไม่ได้บอก

ไฟล์ test มีค่าว่างน้อยกว่า train: เฉลี่ย 2.48 ฟีเจอร์ต่อแถว เทียบกับ 3.71 ใน train เช่น `account_age_days` ว่าง 0.6% ใน test แต่ 14.4% ใน train คะแนนบน test จึงน่าจะสูงกว่า CV แถว train ที่ว่างไม่เกิน 2 ฟีเจอร์ได้ Macro F2 0.803 threshold ที่ดีที่สุดของแต่ละช่วงค่าว่างอยู่ใกล้กัน (0.373 ถึง 0.388) จึงใช้ threshold เดียวได้

## ผลบน Kaggle

ส่งเมื่อ 14 พ.ย. โดยใช้ไฟล์ตัวหลัก (0.72635) แล้วเปลี่ยนเฉพาะคอลัมน์งาน 1 ซึ่งต่างจากเดิม 883 แถว

| ไฟล์ | คะแนนรวม |
|---|---|
| ตัวหลัก | 0.72635 |
| ตัวหลัก + งาน 1 แบบใหม่ | 0.72692 |

คะแนนรวมเพิ่ม 0.00057 ถ้าทุกงานมีน้ำหนักเท่ากัน งาน 1 บน test ดีขึ้นประมาณ 0.0029 ใกล้กับ 0.0032 ที่วัดได้ใน CV ผลในเครื่องจึงใช้ทำนายผลบน test ของงานนี้ได้
