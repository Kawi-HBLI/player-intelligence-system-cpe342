# Task 2: Player Segmentation

จำแนกผู้เล่นเป็น 4 กลุ่ม: Casual (0), Grinder (1), Social (2), Whale (3) วัดด้วย Macro F1

## ข้อมูล

- train 104,000 แถว มี label ครบ
- 34 ฟีเจอร์ตัวเลขและ 10 ฟีเจอร์หมวดหมู่ ค่าว่างเฉลี่ย 8.3%
- สัดส่วนคลาส 39% / 25% / 20% / 15%
- `random_metric_1` ถึง `random_metric_3` เป็น noise ตามที่ datacard ระบุ

## สิ่งที่ EDA เจอ

- ฟีเจอร์ในแต่ละกลุ่มแทบไม่สัมพันธ์กัน ความสัมพันธ์ (Spearman) ที่สูงที่สุดภายในกลุ่มเดียวกันคือ 0.04 ข้อมูลจำลองจึงน่าจะสุ่มค่าแต่ละฟีเจอร์แยกกันโดยขึ้นกับกลุ่มอย่างเดียว
- ไม่มีกฎตายตัวแบบงาน 1 ช่วงค่าของ 4 กลุ่มซ้อนกันเกือบหมด มีแค่ 65 แถวจาก 104,000 ที่ช่วงค่าระบุได้กลุ่มเดียว
- การกระจายของฟีเจอร์ต่อเนื่องเบ้ขวา (skew 0.1 ถึง 0.6) ไม่เป็น Gaussian
- แถวที่ข้อมูลครบทุกช่องได้ Macro F1 0.779 และแถวที่ว่าง 8 ช่องได้ 0.706 ค่าว่างใน test เท่ากับ train (เฉลี่ย 3.8 ฟีเจอร์ต่อแถว)
- โมเดลตัวหลักสับสนระหว่าง Casual กับ Grinder มากที่สุด และทาย Casual เกินจริง (43% เทียบกับที่มีจริง 39%)

## วิธีทำ

ผสมสองโมเดลด้วยค่าเฉลี่ยเรขาคณิตของความน่าจะเป็น ให้น้ำหนัก naive Bayes 0.6 และ CatBoost 0.4

- **naive Bayes ปรับเรียบ** (`pis/task2_naive_bayes.py`) ประมาณความหนาแน่นของแต่ละฟีเจอร์ต่อกลุ่มด้วย histogram 200 ช่องที่ปรับเรียบด้วย Gaussian kernel ฟีเจอร์ที่มีค่าไม่เกิน 40 แบบและฟีเจอร์หมวดหมู่ใช้ตารางความถี่ ช่องที่ว่างไม่ถูกนับเป็นหลักฐาน ตัดคอลัมน์ `random_metric` ออก
- **CatBoost** (MultiClass, depth 6) ใช้ฟีเจอร์หมวดหมู่ตรงๆ ผ่าน `cat_features`
- Stratified 3-fold แล้วเฉลี่ยความน่าจะเป็นที่ผสมแล้วบน test

naive Bayes เหมาะกับงานนี้เพราะสมมติฐานของมัน คือฟีเจอร์เป็นอิสระต่อกันในแต่ละคลาส ตรงกับที่ EDA เจอ

## ผลในเครื่อง

ทุกแถวใช้ fold ชุดเดียวกัน (StratifiedKFold 3, seed 342) รันซ้ำได้ด้วย `python Task2/experiments.py ../cpe342-kaggle-main outputs/exp/task2`

| โมเดล | Macro F1 | logloss |
|---|---|---|
| CatBoost depth 6 (ตัวหลัก) | 0.7516 | 0.6160 |
| CatBoost ตัดคอลัมน์ `random_metric` | 0.7514 | 0.6157 |
| CatBoost เทรน 4,000 รอบ | 0.7515 | 0.6151 |
| CatBoost depth 3 | 0.7530 | 0.6176 |
| CatBoost depth 2 | 0.7528 | 0.6194 |
| CatBoost depth 1 | 0.7539 | 0.6215 |
| naive Bayes แบบ Gaussian | 0.7512 | 0.6395 |
| naive Bayes ปรับเรียบ sigma 5 | 0.7564 | 0.6247 |
| naive Bayes ปรับเรียบ sigma 20 | 0.7513 | 0.6264 |

| **naive Bayes sigma 5 ผสม CatBoost depth 6 (ที่ใช้อยู่)** | **0.7567** | 0.614 |

ผลผ่านโค้ดหลักได้ 0.7567 แต่ละ fold ได้ 0.7546, 0.7582, 0.7573 เทียบกับตัวหลัก 0.7502, 0.7533, 0.7514 ดีขึ้นทุก fold

ที่ลองแล้วไม่ช่วย: ปรับน้ำหนักการตัดสินคลาสให้ Macro F1 สูงสุด (วัดแบบแยกชุดปรับกับชุดวัดได้ 0.7562 ถึง 0.7572 จากทุกโมเดล), ผสมสามโมเดล, กฎจากช่วงค่า

ทุกแนวทางที่ดีไปชนกันที่ 0.756 ถึง 0.757 และต้นไม้ยิ่งตื้นยิ่งดี จึงน่าจะเป็นเพดานของข้อมูลชุดนี้

## ตรวจบน Kaggle

ส่งไฟล์ที่เปลี่ยนงาน 1 และงาน 2 จากตัวหลัก (15 พ.ย.) ได้ 0.72792 เทียบกับไฟล์ที่เปลี่ยนงาน 1 อย่างเดียว 0.72692 งาน 2 จึงให้ +0.00100 บนคะแนนรวม

คะแนนรวมเป็นค่าเฉลี่ยของ 5 งาน ส่วนต่างนี้จึงเท่ากับ Macro F1 ของงาน 2 เพิ่มประมาณ 0.005 บน test เท่ากับที่วัดได้ในเครื่อง (+0.0051) การวัดด้วย 3-fold ของเราจึงใช้ทำนายผลบน test ได้

## บทเรียนจากข้อมูลชุดเก่า

ข้อมูลชุดแรกถูกสร้างเรียงตามกลุ่มโดยไม่ได้สลับลำดับ เลขใน `player_id` จึงบอกกลุ่มได้เกือบตรงๆ decision tree บนเลข id อย่างเดียวได้ Macro F1 0.968 ขณะที่ฟีเจอร์พฤติกรรมทั้งหมดได้ 0.749 ผู้จัดสลับเลข id ในชุดใหม่ โมเดลเดียวกันจึงเหลือ 0.143 เราเอาฟีเจอร์เลข id ออกจากโค้ดแล้ว
